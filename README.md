# 漠翠自用进销存 · Cloudflare Final 1.0

这是王佳铭自用的单账号进销存系统，不面向客户，不包含商城、代理端或多商户收费功能。

## 当前功能

- 商品：新增、编辑、复制、分类、颜色、成本价、销售价、库存、图片、商品备注、自动编码、模糊搜索、CSV 批量导入。
- 库存：手工入库、出库、单品盘点、批量盘点、完整库存流水。
- 销售：客户姓名模糊匹配、多商品开单、折扣、优惠、抹零、实收、撤销、恢复、复制重新开单。
- 调借：借出、借入、调入、历史借调人匹配、超期提醒、再次借货、初次借货图片与文字备注。
- 还货：全部归还、部分归还、单件归还；每一次还货独立保存时间、图片、商品数量和文字备注。
- 借调售出：借出商品售出不重复扣库存；自动生成正式销售单并联通销售、库存流水、利润和统计。
- 凭证：隐藏的借调协议/调拨交接单入口、双方手写签名、确认图片、微信确认文案、打印/PDF。
- 报表：经营概况、销售额、利润、库存成本、客户排名、商品排名。
- 云端：手机和电脑共用一套数据、版本冲突提示、最近 50 个云端历史版本、R2 私有图片存储。
- 备份：云端历史恢复 + 本地 JSON 独立备份。

## Cloudflare 架构

- Worker：登录、同步、图片、备份与静态网页接口。
- Static Assets：手机和电脑共用网页/PWA。
- D1：账号、会话、同步版本和审计元数据。
- R2：业务快照、商品图片、借货/还货图片和签字凭证。
- IndexedDB：当前设备缓存，提升操作速度。

`wrangler.jsonc` 使用 Cloudflare 自动资源配置：首次部署时会自动创建并绑定 D1 和 R2，不需要手工填写数据库 ID。

## 第一次部署

1. 解压最终 ZIP。
2. 在 GitHub 仓库点击 `Add file → Upload files`。
3. 上传解压目录里面的全部文件和文件夹。
4. Commit 到 `main`。
5. Cloudflare Workers Builds 自动部署。
6. 打开部署网址，按 `FIRST_LOGIN.txt` 完成首次初始化。

详细步骤见：`docs/UPLOAD_TO_GITHUB.md` 和 `docs/FIRST_DEPLOY.md`。

## 以后更新

以后只需把更新文件提交到 GitHub 的 `main` 分支，Cloudflare 会自动构建并更新手机、电脑共用的网址，不再手工上传 Pages ZIP。

## 重要数据规则

- 库存变化必须通过入库、出库、盘点、销售、撤销、调借、归还或借调售出产生流水。
- 借出时已经扣过仓库库存，借出商品后来售出不会再次扣库存。
- 销售撤销会反向恢复对应业务状态；恢复销售会重新执行对应状态变化。
- 云端同步不是独立备份，仍建议每周导出一次 JSON 保存到 iCloud。

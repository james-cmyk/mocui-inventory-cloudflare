# 漠翠进销存 v2.0 Local-First 第一阶段

## 本次改动
1. 业务写入不再等待首次云端同步完成。
2. 云端 Pull 不再 clear 本机数据库；改为按 ID 合并并 upsert。
3. 每次本机写入完成后立即记录“待同步”状态。
4. 云端失败不影响本机数据继续保存。
5. 409 多设备冲突不再 force 覆盖，先合并再重试。
6. 网络恢复后自动续传。
7. 页面状态明确区分：
   - 本机已保存 · 等待云端同步
   - 本机数据安全 · 正在后台同步
   - 本机已保存 · 云端已确认
   - 本机数据安全 · 网络恢复后自动同步

## 覆盖方法
把 ZIP 内 `public/` 下两个文件上传到仓库同名位置：
- `public/index.html` 覆盖原文件
- `public/local-first-v2.js` 新增

其他文件先不要删，也不要改。

## 必测 8 项
每项至少做 5 次。

1. 新增商品 → 保存后 1 秒内杀 App → 重开，商品仍在。
2. 新增调借 → 保存后立刻杀 App → 重开，调借和库存都仍在。
3. 销售开单 → 保存后立刻切飞行模式并杀 App → 重开，销售仍在。
4. 断网状态新增商品/调借/销售 → 连续操作 → 重开数据仍在。
5. 显示“同步中”时杀 App → 重开本机数据仍在，并继续同步。
6. Wi‑Fi / 移动网络 / 代理切换时保存数据 → 本机数据不消失。
7. 两台设备先后修改不同记录 → 最终两边都能看到。
8. 调货货源库上传图片失败/中断 → 文字、来源、报价不能消失。

## 判定
只有 1-7 全部通过，才把 v2.0 第一阶段视为合格。
第 8 项图片队列会在第二阶段单独升级成“先存本地记录、图片后台续传”。

## 当前限制
本阶段仍兼容现有 `/api/sync` 整库快照接口，因此它是“本地安全内核第一阶段”，还不是最终的 D1 增量 Outbox 架构。
后续第二阶段要增加：
- IndexedDB outbox
- operationId 幂等
- D1 增量操作日志
- tombstone 删除同步
- 图片持久上传队列
